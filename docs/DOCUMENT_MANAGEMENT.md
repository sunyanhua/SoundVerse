# 项目文档管理制度

## 1. 制度目标

规范项目文档的创建、存储、归档和清理流程，确保文档整洁、可追踪、易查找。

## 2. 文件夹结构

```
docs/
├── README.md                    # 文档中心索引
├── DOCUMENT_MANAGEMENT.md       # 本文档 - 文档管理制度
├── tasks/                       # 任务清单目录
│   └── {版本号}/
│       ├── phase-*.md           # 各阶段任务清单
│       └── ...
├── Audit_Report/                # 管家质检报告
│   ├── README.md                # 质检报告索引
│   ├── Archive/                 # 历史报告归档
│   └── Audit_{日期}_{时间}_R{轮次}.md
└── backend/                     # 后端相关文档
    └── PROGRESS_ARCHIVE.md      # 进度归档
```

## 3. 文档分类规范

### 3.1 任务清单 (tasks/)
- **用途**: 存放各版本的任务清单文件
- **命名**: `{版本号}/phase-{序号}-{阶段名}.md`
- **更新**: 任务完成后标注状态和时间戳
- **保留期**: 长期保留

### 3.2 质检报告 (Audit_Report/)
- **用途**: 存放管家生成的代码质检报告
- **命名**: `Audit_{日期}_{时间}_R{轮次}.md`
- **归档**: 超过5轮的旧报告移至 Archive/
- **保留期**: 1年，之后移至 Archive/

### 3.3 进度归档 (backend/)
- **用途**: 存放历史进度记录
- **命名**: `PROGRESS_ARCHIVE.md`
- **更新**: 大版本结束后归档
- **保留期**: 永久保留

## 4. 临时文档管理

### 4.1 临时文档定义
- 以 `temp_` 开头的文件
- 包含 `draft`、`tmp`、`temp` 字样的文件
- 报告的检查报告类文件（非最终版）

### 4.2 清理规则
| 类型 | 清理周期 | 处理方式 |
|------|----------|----------|
| 检查报告草稿 | 立即 | 删除或归档至 archive/ |
| 临时设计稿 | 每周 | 清理过期文件 |
| 会议纪要草稿 | 每月 | 归档或删除 |

## 5. 归档流程

1. **识别**: 识别不再活跃的文档
2. **标记**: 在文档顶部添加归档标记
```markdown
---
**归档状态**: 已归档
**归档日期**: 2026-04-05
**原因**: 版本迭代，内容已合并
---
```
3. **移动**: 移至对应的 Archive/ 目录
4. **索引**: 在 Archive/README.md 中记录

## 6. 禁止事项

- ❌ 在根目录存放文档文件（README.md 除外）
- ❌ 创建重复的检查报告文件
- ❌ 超过 30 天的临时文件不清理
- ❌ 在 tasks/ 中存放非任务清单文件

## 7. 索引维护

所有重要文档必须在对应目录的 README.md 中登记索引。
